# Firmware Architecture Decision Records

This folder records firmware decisions that have meaningful alternatives and consequences beyond
one implementation detail. Each ADR states its scope and status, the context, the decision, the
alternatives considered, and resulting trade-offs. Use Git history for routine revisions; add dates
only when they identify time-sensitive evidence or a tested revision.

ADRs explain why a decision was made. Feature documents define behavior, research records evidence,
and architecture documents describe the concrete design. A decision can be superseded by a later
ADR; preserve the earlier record and link the replacement.
