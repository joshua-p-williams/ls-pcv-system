# Open questions

This register coordinates follow-up for unresolved hardware checks and design choices. Component and interface pages retain technical details and final decisions; [project status](status.md) summarizes progress. A documented interface is not a verified connection.

## Start here for W01

**Q01 is resolved:** W01 will define the complete bench wiring for the controller, display, ADC, sensor and conditioning, with phased assembly and verification against that design. See the [W01 scope and assembly approach](../hardware/wiring/README.md#w01-scope-and-assembly). **Q02 is resolved:** W01 uses the N16R8 development board; the XIAO remains the finished-gauge target with its own wiring and verification. **Q03 is resolved:** use one USB source at a time, accepting restart when switching between computer and standalone supply. The N16R8 board has not yet arrived: **Q04** physical identification and Q05/Q12 board measurements await receipt. Q15 selects one multifunction button; Q24 selects the initial gesture mapping. Q23 selects fixed brightness initially with provision for later software configuration and persistent settings. Continue the remaining hardware and wiring choices while retaining provisional hardware assumptions.

The complete bench design requires **Q04-Q10, Q12 and Q14-Q18** as applicable to the selected controller and interfaces. Converter-powered operation adds **Q11 and Q19**. XIAO-specific **Q13** applies only if that board is used. **Q20-Q22** concern operational validation or later vehicle work; they do not all block drafting a bench harness.

Draft W01 can show unresolved work, but assembly-ready connections require the relevant evidence. Tests needing a wired fixture follow verification of its terminal mapping and electrical limits; the register does not require a finished gauge before designing that fixture.

## Maintaining the register

- Keep IDs stable; append new IDs without renumbering existing entries. Grouping and display order may change as dependencies become clearer.
- Use **Open**, **Investigating** or **Resolved**. Mark Investigating when evidence collection or evaluation actually begins. If a question becomes inapplicable, record the scope decision and resolve it with that explanation.
- Record the answer, rationale and evidence in the relevant component/interface document first, then add a brief answer/link here and update status. Strike through the question text when resolved; retain the ID, status and readable answer so references stay useful.
- A design selection can resolve a decision without proving hardware behavior. Keep associated verification questions open until their own evidence exists.
- Place new photos or source documents in `_staging/inbox/<batch>/` for review and sanitized import. Public answers must link to public project records, not ignored staging files. For measurements, use the [data conventions](../data/README.md).
- Update affected harnesses and [project status](status.md) when answers change their readiness. This register tracks follow-up, not every implementation task or historical assumption.
